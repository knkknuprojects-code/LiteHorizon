# Phase 4: порівняння донавчання та дистиляції DistilGPT-2

## 1. Місце в основному проєкті

Цей каталог містить **два самостійні Jupyter-експерименти**:

* `distilgpt2_finetune.ipynb` — повнопараметричне донавчання `distilgpt2` за cross-entropy (CE).
* `distilgpt2_logit_distillation.ipynb` — повнопараметричне донавчання `distilgpt2` з фіксованим учителем `gpt2-medium` за сумою CE та KL-дивергенції.

**Розташування в репозиторії Horizon:**

```text
Horizon/
└── experiments/
    └── phase4/
        └── distilgpt2_wikitext/
            ├── distilgpt2_finetune.ipynb
            ├── distilgpt2_logit_distillation.ipynb
            └── README.md
```

Каталог належить до допоміжних експериментів Phase 4 і відокремлений від основного програмного коду `src/horizon/training/`. Ноутбуки запускаються незалежно від API Horizon.

**Зв'язок із Phase 4 (fine-tuning / model adaptation).** Це найраніший етап розробки Horizon, на якому задача адаптації мовних моделей має практичне значення. Фази 0–3 охоплюють програмний каркас, інференс, структурований аналіз і кластеризацію без навчання мовних моделей. Phase 4 охоплює підготовку навчальних даних, донавчання й оцінювання (`src/horizon/training/export.py`, `train.py`, `evaluate.py`). Два ноутбуки доповнюють цей етап окремим методичним експериментом із порівняння звичайного донавчання компактної моделі та дистиляції знань. Вони не входять до виконуваного конвеєра Horizon і **не відтворюють E4** зі статті.

## 2. Співвідношення експерименту з основним Horizon

||Ці ноутбуки|Основний Horizon, Phase 4 / E4|
|-|-|-|
|Завдання|Прогнозування наступного токена|Структурований JSON `Analysis` для сканування горизонту|
|Корпус|WikiText-2|Зібрані тексти та аналізи Horizon|
|Модель|`distilgpt2`; учитель `gpt2-medium` лише в другому ноутбуці|Qwen2.5-0.5B-Instruct у зафіксованому E4|
|Метод|Оновлення всіх ваг студента: CE або CE+KL|Parameter-efficient fine-tuning (LoRA)|
|Метрика|Perplexity на відкладеному WikiText-2|Валідність JSON, зіставлення полів, ресурсні показники|
|Роль у проєкті|Самостійний допоміжний експеримент Phase 4|`horizon export → training.train → training.evaluate`|

**Термінологічне уточнення.** В основному Horizon модель Gemini може виконувати роль *учителя розмітки*, створюючи цільові об'єкти `Analysis`. Тут `gpt2-medium` є *вчителем розподілів токенів*: його логіти задають KL-компонент функції втрат. Це різні способи перенесення знань; не слід називати їх одним і тим самим експериментом.

## 3. Підготовка до запуску

Потрібні: Python **3.12** (або сумісний сучасний Python), інтернет для першого завантаження моделей і WikiText-2, дискове місце для кешу Hugging Face, достатня оперативна/відеопам'ять. Можливий запуск на CPU, але він суттєво повільніший. **GPU необов'язковий.** Код обирає CUDA, якщо вона доступна, інакше CPU; MPS (Apple Silicon) автоматично не обирається.

Рекомендовано **окреме віртуальне середовище**, щоб бібліотеки цього експерименту не змінювали набір залежностей Horizon. Перейдіть до кореня репозиторію `Horizon/` та виконайте (Linux / macOS):

```bash
python3.12 -m venv .venv-distilgpt2
source .venv-distilgpt2/bin/activate
python -m pip install --upgrade pip
python -m pip install "torch>=2.2" "transformers>=4.44,<5" "datasets>=2.20" "tqdm>=4.66" "jupyterlab>=4" "ipykernel>=6"
python -m ipykernel install --user --name horizon-distilgpt2 --display-name "Horizon · DistilGPT-2"
jupyter lab experiments/phase4/distilgpt2_wikitext/
```

У Windows PowerShell замість першої пари команд використайте:

```powershell
py -3.12 -m venv .venv-distilgpt2
.\.venv-distilgpt2\Scripts\Activate.ps1
```

Далі виконайте ті самі `python -m pip ...` та `jupyter lab ...` команди. Якщо локально вже встановлено PyTorch під іншу платформу/CUDA, використовуйте варіант встановлення PyTorch, відповідний саме вашому середовищу; наведена команда не гарантує GPU-збірку. Перевірте, що обрано ядро **Horizon · DistilGPT-2**.

Перший запуск звернеться до Hugging Face: `distilgpt2`, `gpt2-medium`, токенізатора `gpt2` і датасету `Salesforce/wikitext` (`wikitext-2-raw-v1`). За обмеженого доступу або відсутності інтернету заздалегідь закешуйте ці ресурси у спосіб, що відповідає вашому середовищу. Токен доступу зазвичай не потрібен для цих відкритих репозиторіїв, але ліміти завантаження можливі.

Ці ноутбуки використовують моделі повного розміру, а не LoRA; **не запускайте два навчання паралельно на одному обмеженому GPU**. Для порівняння виконання варто використовувати ту саму машину та версії бібліотек.

## 4. Як виконати обидва експерименти

1. Відкрийте **`distilgpt2_finetune.ipynb`**, запустіть `Run All` / `Restart Kernel and Run All`. Буде завантажено початковий `distilgpt2`, відібрано 2000 текстів WikiText-2, виконано 2 епохи та обчислено perplexity на 500 валідаційних текстах.
2. Закрийте ядро першого ноутбука або перезапустіть його, щоб звільнити пам'ять. Відкрийте **`distilgpt2_logit_distillation.ipynb`** і так само запустіть комірки. Буде завантажено `gpt2-medium` як нерухомого вчителя, `distilgpt2` як студента, виконано 2 епохи з CE+KL та обчислено perplexity учителя, початкового студента і студента після навчання.
3. Зіставляйте насамперед **perplexity** на валідаційному наборі, а не числа навчальної функції втрат: у другому ноутбуці loss включає KL і тому за означенням відрізняється. Нижча perplexity означає кращу передбачуваність токенів WikiText-2, але **не** кращий пошук сигналів або трендів.

У двох ноутбуках параметри прописані безпосередньо в коді: 2000 прикладів навчання, 500 валідації, фільтр `len(text.strip()) > 50`, послідовності довжиною 128, `batch_size=8`, `lr=5e-5`, 2 епохи. У дистиляції: `T=2`, `alpha=0.3`, тому `loss = 0.7 * CE + 0.3 * T² * KL`. В обох випадках паддинг маскується. Валідаційний набір береться з `validation`, а не з `train`.

**Налаштування не змінено під час очищення**, крім вилучення в `finetune` одного повторного завантаження `distilgpt2` у змінну `original`, яка ніде не використовувалася. Тому відновлення історичних значень залежить від початкового випадкового стану, порядку прикладів і середовища: в оригіналах **не встановлено seed** і немає повторних прогонів. Для науково контрольованого нового порівняння слід спершу зафіксувати seed (`random`, `numpy`, `torch`, DataLoader), апаратне середовище, версії моделей і бібліотек, виконати кілька незалежних запусків та навести варіативність. **Таке нове порівняння не виконане** цими файлами.

## 5. Результати експериментів та їх інтерпретація

Наведено **зафіксовані результати окремих запусків**, збережені в таблицях наприкінці кожного ноутбука. Повторного навчання під час підготовки цього комплекту не проводили; фактичні показники нового запуску можуть відрізнятися.

|Модель / метод|Історична perplexity (WikiText-2 validation)|
|-|-:|
|Початковий `distilgpt2`|74,28 *(виміряно в ноутбуці дистиляції)*|
|Студент після звичайного донавчання|**43,32**|
|Студент після дистиляції|**38,97**|
|Учитель `gpt2-medium`|36,75|

Різниця 43,32 проти 38,97 — корисний привід для контрольованого дослідження, **не** статистично доведена перевага дистиляції: жодного спільного зафіксованого seed, повторів чи довірчих інтервалів немає. Також це не доводить прискорення інференсу: обидва студенти мають той самий розмір, а навчання з учителем у вихідному журналі було довшим.

## 6. Як результати експериментів пов'язані з основним Horizon

У Phase 4 Horizon досліджує адаптацію мовних моделей для роботи в умовах обмежених обчислювальних ресурсів. Цей допоміжний експеримент розглядає один з аспектів тієї самої задачі: вплив способу навчання на якість компактної моделі за незмінної архітектури студента.

* **Методичний зв'язок.** Обидва ноутбуки реалізують цикл підготовки даних, адаптації моделі та оцінювання на відкладеній вибірці. Це відповідає загальній логіці Phase 4 (`export → train → evaluate`), хоча конкретні дані, функції втрат і метрики відрізняються.
* **Альтернативний механізм адаптації.** Порівняння CE та CE+KL доповнює дослідження LoRA окремим прикладом перенесення знань від більшої моделі до компактної. На відміну від генерації навчальних міток моделлю-вчителем у Horizon, тут використовується розподіл імовірностей токенів учителя.
* **Зв'язок результатів із ресурсною орієнтацією Horizon.** Зафіксована perplexity студента після дистиляції (38,97) нижча, ніж після звичайного донавчання (43,32), за однакової архітектури студента. Це ілюструє можливість покращення моделі через зміну способу навчання без збільшення її розміру. Результат є попереднім: він не встановлює статистичної переваги дистиляції, не підтверджує економії ресурсів під час навчання та не вимірює швидкості інференсу.
* **Межі застосовності.** Perplexity на WikiText-2 характеризує прогнозування наступного токена, а не якість структурованого аналізу Horizon. Перенесення висновків на формування JSON `Analysis` потребує окремої перевірки на даних Horizon, з узгодженим протоколом оцінювання та сумісною токенізацією учителя і студента.

Таким чином, експеримент є самостійним методичним доповненням Phase 4, що демонструє альтернативний механізм адаптації компактних мовних моделей. Його результати не входять до доказової бази E4 у `4u_2026di-refs-corrected-30oct.docx` і не є оцінкою якості LiteHorizon.

## 7. Походження та обсяг очищення

Матеріал перенесено з двох самостійних файлів `IT-DistilGPT-regular.ipynb` і `IT-DistilGPT-distil.ipynb`. 

Очищення обмежене оформленням і невикористаною операцією в першому ноутбуці: прибрано номери запусків, старі прогрес-бари, попередження та службові outputs; історичні цифри перенесено в явно позначені Markdown-таблиці. Відповідний код функцій втрат, підготовки даних, навчання й оцінювання збережено; повний алгоритмічний код `distilgpt2_logit_distillation.ipynb` залишився незмінним. У структурі проєкту експеримент має статус допоміжного матеріалу Phase 4; виконуваний код `src/horizon/` та результати статті залишаються незалежними від нього.

**Перевірено під час пакування:** формат `.ipynb`, синтаксис Python у кожній кодовій комірці та відсутність збережених виконань. **Не перевірено в цьому середовищі:** встановлення повного ML-стека, завантаження моделей/датасету, фактичне навчання та нові значення perplexity.
