# Публікація LiteHorizon через GitHub: інструкція

## Що означає `knkknu / projects`

Якщо на GitHub ви бачите `knkknu / projects` у верхній частині сторінки
репозиторію, то `knkknu` — власник, а `projects` — **назва вже наявного
репозиторію**. Репозиторії не вкладаються один в інший. Додати LiteHorizon в
нього можна тільки як папку, але це погіршує окремі релізи, CI, issues і
цитування.

**Рекомендовано:** новий окремий репозиторій `LiteHorizon` **під тим самим
власником** `knkknu`, якщо ваш обліковий запис має на це права. Уже наявний
`projects` може містити посилання на цей репозиторій у своєму README.

Якщо `projects` — не репозиторій, а дошка GitHub Projects, створіть репозиторій
`LiteHorizon` під власником `knkknu` і потім зв'яжіть їх через налаштування
GitHub Projects / репозиторію. Якщо `knkknu` є організацією, у формі New repository
виберіть її у списку **Owner**.

## Варіант 1: через браузер і GitHub Desktop

1. Розпакуйте `LiteHorizon_github_ready.zip`. Усередині має бути одна папка
   `LiteHorizon/` із `README.md`, `src/`, `tests/` тощо.
2. Ознайомтеся з `docs/PUBLISHING_GATES.md`. Доти залишайте репозиторій закритим.
3. На GitHub відкрийте https://github.com/new. У полі **Owner** виберіть
   потрібний акаунт або організацію; **Repository name**: `LiteHorizon`;
   **Visibility**: `Private`.
4. Не вибирайте автоматичне створення README, `.gitignore` або License,
   оскільки підготовлений пакет уже містить ці файли.
5. Встановіть GitHub Desktop із https://desktop.github.com/.
6. У GitHub Desktop оберіть **File → Add local repository** і вкажіть папку
   `LiteHorizon`. Якщо Git ще не ініціалізовано, створіть локальний репозиторій
   для цієї папки; не вибирайте батьківський каталог із ZIP і PDF.
7. Перевірте список файлів у вкладці Changes. У ньому **не повинно бути**
   `.horizon.env`, корпусів, ключів, великих моделей або приватних XLSX.
8. Створіть перший commit та опублікуйте його в щойно створений репозиторій.
   Якщо GitHub Desktop пропонує окремо створити віддалений репозиторій, не
   створюйте дублікат: зв'яжіть існуючий GitHub remote з локальним.
9. Перевірте вкладку **Actions**, README, відображення CITATION, потрібну
   видимість і дозволи. Public встановлюйте лише після остаточного погодження
   авторства, ліцензії та прав на дані.

## Варіант 2: Git у командному рядку

На GitHub створіть **порожній приватний** репозиторій. У папці `LiteHorizon`:

```bash
git init -b main
git add .
git status
git commit -m "Prepare LiteHorizon research release candidate"
git remote add origin https://github.com/OWNER/LiteHorizon.git
git push -u origin main
```

Замініть `OWNER` реальним власником; URL у прикладі **не підтверджує існування
віддаленого репозиторію**. Якщо власник — `knkknu`, URL матиме вигляд
`https://github.com/knkknu/LiteHorizon.git` після фактичного створення.
Для доступу GitHub може запросити браузерну автентифікацію або PAT через
credential manager; пароля акаунта для HTTPS Git більше недостатньо.

## Як зв'язати з наявним `projects`

- Якщо `projects` — репозиторій: додайте посилання на `LiteHorizon` до його
  README або Project Index. Не копіюйте повністю код удруге.
- Якщо `projects` — GitHub Projects: відкрийте репозиторій `LiteHorizon` →
  вкладка Projects → **Link a project**, або в налаштуваннях дошки додайте
  потрібний репозиторій як пов'язаний (доступні кнопки залежать від прав).

## Після публікації

Зробіть release з точним тегом, зафіксуйте commit у статті, додайте DOI через
архівування релізу (наприклад, Zenodo), якщо відповідна команда погодила це.
Не вигадуйте DOI до його фактичної реєстрації.
